# Git 发布

## 认证

编辑器使用系统 Git CLI，不自行保存 HTTPS 令牌。认证来源：

- Git Credential Manager / 系统凭据助手
- SSH Agent 与已有 SSH 配置

仓库地址不能包含 `https://user:token@...` 形式的明文凭据；设置页会拒绝并提示。日志与错误信息中的凭据会被替换为 `***`。

## 首次发布

1. 设置远端地址与分支，点击「测试 Git」确认 `ls-remote` 可解析。
2. 工作副本不存在时，编辑器执行 `git clone --branch <branch> --single-branch <remote> <worktree>`；若目录已存在且非空但不是 Git 仓库，会提示选择空目录，并保留本地已有数据。
3. 校验 `origin` 与配置一致、当前分支一致。
4. 检查仓库兼容性：存在 `data/`，且 `.github/workflows/` 下有 Pages 工作流。
5. 发布前 `fetch --prune origin`；本地落后且无本地提交时快进；双方都有新提交时报分叉，绝不强推。

## 提交范围

只暂存：

- `data/calendar.json`
- `data/photos/**`

不提交 API Key、访问令牌、应用配置、构建产物或用户目录中的其他文件。若工作副本存在与发布无关的未提交修改，发布停止并列出这些文件，不暂存、不清理。

提交信息为 `calendar: publish entries`。若没有待提交内容但存在未推送提交，重试会复用已有提交，不重复生成提交。

## 推送失败

| 情况 | 行为 |
| --- | --- |
| 认证失败 | 保留本地提交与照片，提示检查系统凭据/SSH Agent；修复后可重试 |
| 非快进/远端拒绝 | 停止并提示先同步；保留本地提交，不强推 |
| 网络失败 | 保留本地待发布状态；恢复网络后重试 |
| Pages 构建失败 | 数据已推送；编辑器和文档提供 Actions 入口，不谎报已上线 |

推送成功后编辑器显示提交哈希、时间、Pages 链接与「Pages 正在构建」说明；部署状态不可读时只给 Actions 链接。

## 回滚

- 内容回滚：revert 发布提交或恢复旧的 `data/calendar.json` 与照片，推送后 Pages 重新部署。
- 冲突恢复：若本地与远端分叉，先手动同步（例如在终端 `git pull --rebase` 并解决冲突），再回到编辑器发布；编辑器不会自动变基或强推。

## 串行化

同一编辑器实例内发布操作使用互斥锁串行执行；发布进行中再次点击不会启动第二个 Git 进程。发布期间导入的新照片保留为待发布状态，当前发布结束后再进入下一批。
