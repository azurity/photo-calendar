# calendar-display Specification

## Purpose
为访客提供纯静态的照片日历展示：既能按月浏览整月的照片，也能进入某一天沉浸式查看照片与文案；没有照片的日期同样有稳定、可复现的寄语与图样，让每一天都值得被打开。

## Requirements

### Requirement: 月历网格

月历视图 SHALL 以周一为每周首日，展示所选公历月份的全部日期；每个日期格 SHALL 显示日号，并在该日有条目时显示照片缩略图。今天与当前查看的日期 SHALL 具有可区分的视觉标记。

#### Scenario: 渲染指定月份

- **WHEN** 访客打开 `index.html?month=2026-11`
- **THEN** 页面显示 2026 年 11 月的完整周网格，包含 11 月 1 日至 11 月 30 日，且非本月的补位日期不以可点击日期呈现

#### Scenario: 无照片的日期格为空

- **WHEN** 某日期没有配置照片
- **THEN** 该日期格只呈现日期信息，不显示照片、破图图标或占位照片

#### Scenario: 有照片时显示缩略图

- **WHEN** 某日期存在有效条目与缩略图
- **THEN** 该日期格显示对应缩略图，且缩略图使用该条目的日期作为可访问名称的一部分

#### Scenario: 标记今天

- **WHEN** 今天处于当前展示的月份内
- **THEN** 今天的日期格具有与普通日期格可区分的视觉标记，并带有面向辅助技术的「今天」说明

### Requirement: 月历导航与深链接

月历视图 SHALL 支持切换到上一月、下一月、回到今天，以及点击日期进入该日单日页。当前月份 SHALL 写入 URL 查询参数，使刷新、收藏和分享后仍停留在同一个月；非法或缺失的月份参数 SHALL 回退到当前月份。

#### Scenario: 翻月并更新 URL

- **WHEN** 访客点击「下一月」
- **THEN** 月历切换到下一个月，URL 的月份参数同步更新，且页面不整页刷新

#### Scenario: 回到今天

- **WHEN** 访客点击「今天」
- **THEN** 月历切换到当前月份，并突出显示今天

#### Scenario: 非法月份参数

- **WHEN** URL 中的月份不是合法的 `YYYY-MM`，或月份超出 01–12
- **THEN** 页面展示当前月份，并将 URL 规范化为当前月份，不出现空白或报错页

#### Scenario: 从月历进入单日

- **WHEN** 访客点击 2026 年 11 月 8 日的日期格
- **THEN** 页面跳转到单日页，日期参数为 `2026-11-08`

### Requirement: 单日视图

单日视图 SHALL 展示所选日期的星期、日期和该日内容。该日有照片时，照片 MUST 是页面主体，文案作为辅助；该日没有照片时，页面 MUST 展示一句来自固定语句库的寄语，并以 CSS 图样作为背景，不得显示破图或空白主体。

#### Scenario: 展示有照片的日期

- **WHEN** 访客打开 `day.html?date=2026-11-08`，且该日有照片与文案
- **THEN** 页面以照片为视觉主体，同时显示日期、星期和完整文案，照片带有描述性替代文本

#### Scenario: 展示无照片的日期

- **WHEN** 访客打开某一天，且该日没有配置照片
- **THEN** 页面展示固定语句库中的一句寄语和 `css-doodle` 图样背景，且不请求不存在的照片文件

#### Scenario: 单日页前后导航

- **WHEN** 访客在单日页点击「前一天」或「后一天」
- **THEN** 页面切换到相邻日期并更新 URL，跨月时日期与月份信息同步正确

#### Scenario: 非法的日期参数

- **WHEN** URL 中的日期不是合法的 `YYYY-MM-DD`，例如 2026-02-30
- **THEN** 页面回退到今天，并显示一条不阻塞浏览的提示

### Requirement: 响应式布局

展示页 SHALL 在 320px 至 1920px 的视口宽度内可用，不得出现横向滚动；月历在窄屏上仍须可读且日期格可触控，单日页的照片 MUST 按视口宽度自适应。所有交互控件的可触控区域 SHOULD 不小于 44×44 CSS 像素。

#### Scenario: 移动端浏览月历

- **WHEN** 在 375×667 的视口中打开月历页
- **THEN** 月历完整落在视口内，无横向滚动，日期格文字与缩略图清晰可辨，日期格可被手指点击

#### Scenario: 桌面端浏览单日页

- **WHEN** 在 1440×900 的视口中打开有照片的单日页
- **THEN** 照片按比例完整显示，不拉伸变形，不超出视口造成滚动

#### Scenario: 减少动态效果偏好

- **WHEN** 操作系统启用 `prefers-reduced-motion: reduce`
- **THEN** 页面关闭或显著减弱过渡与动画，内容仍然完整可读

### Requirement: 确定性回退内容

没有照片的日期 SHALL 仅依据日期字符串与固定内容库版本确定寄语和图样；同一部署版本下，同一天在刷新、重新打开、不同设备与不同视口下 MUST 得到相同的寄语与图样。选择过程 MUST NOT 依赖 `Math.random`、当前时间或浏览器随机状态。

#### Scenario: 刷新后内容不变

- **WHEN** 访客在同一天多次刷新无照片的单日页
- **THEN** 每次看到的寄语文本与图样完全一致

#### Scenario: 跨设备一致

- **WHEN** 两个不同设备在同一部署版本下打开同一个无照片日期
- **THEN** 两个设备展示相同的寄语和图样

#### Scenario: 不同日期可得到不同内容

- **WHEN** 两个不同日期分别打开单日页
- **THEN** 系统允许它们得到不同寄语或不同图样，不强制每日轮换或固定顺序

### Requirement: 内容层级与可读性

有照片的日期 SHALL 以照片为绝对视觉主体，文案和日期信息不得遮挡照片关键区域；无照片的日期 SHALL 以寄语为主要文本，图样只作为背景。两种状态下正文与背景的对比度 MUST 满足 WCAG AA 的普通文本要求。

#### Scenario: 有照片时文案不喧宾夺主

- **WHEN** 单日页展示有照片的日期
- **THEN** 照片占据主要视觉区域，文案以清晰但次要的层级呈现，且不覆盖照片主体不可读

#### Scenario: 无照片时寄语是主体

- **WHEN** 单日页展示无照片的日期
- **THEN** 寄语在视觉层级上明显高于装饰图样，图样不遮挡文字或降低文字对比度

### Requirement: CSS 图样与降级

无照片日期的背景图样 SHALL 使用 `css-doodle` 渲染，并从固定版本的 CDN 资源加载。CDN 不可用、脚本加载失败或脚本被禁用时，页面 MUST 回退到纯 CSS 渐变或纹理背景，寄语和导航保持可读、可用。

#### Scenario: 使用 css-doodle 渲染图样

- **WHEN** 无照片日期正常加载且 CDN 可用
- **THEN** 页面使用与日期对应的固定图样作为背景，刷新后图样不变

#### Scenario: CDN 加载失败

- **WHEN** `css-doodle` 脚本无法加载
- **THEN** 页面显示预留的 CSS 背景，不出现空白背景、报错弹窗或无法阅读的文字

### Requirement: 数据加载与故障回退

展示页 SHALL 从同源 `data/calendar.json` 读取日历数据，并使用数据中的更新时间避免读到过期缓存。数据加载中 SHALL 有可感知的加载状态；数据缺失、格式无效或单张照片加载失败时，页面 MUST 降级为无照片展示，不得整体崩溃或出现破图。

#### Scenario: 正常加载数据

- **WHEN** 展示页请求 `data/calendar.json` 且返回有效数据
- **THEN** 页面按条目展示对应日期的照片与文案，且请求 URL 带有反映数据版本的缓存失效参数

#### Scenario: 数据文件缺失或无效

- **WHEN** `data/calendar.json` 返回 404、非法 JSON 或不符合数据契约
- **THEN** 月历与单日页仍可打开，所有日期按无照片状态展示，并给出不阻塞浏览的数据提示

#### Scenario: 单张照片加载失败

- **WHEN** 某条目的照片文件返回 404 或解码失败
- **THEN** 该日期按无照片状态展示寄语与图样，不显示破图图标

### Requirement: 文案渲染安全与可访问性

文案和所有来自数据文件的文本 MUST 作为纯文本渲染，不得作为 HTML 执行。页面 SHALL 提供语义化的标题层级、可聚焦的交互控件、可见的焦点样式，以及照片的描述性替代文本；单日页 SHOULD 提供日期、文案与照片的 Open Graph 元数据以便分享。

#### Scenario: 文案中包含 HTML

- **WHEN** 某条目的文案为 `<script>alert(1)</script>` 或包含其他 HTML 标签
- **THEN** 页面按字面文本显示该内容，脚本不执行，页面结构不被破坏

#### Scenario: 键盘浏览

- **WHEN** 访客仅使用 Tab 与 Enter 操作页面
- **THEN** 所有导航链接和日期格均可聚焦、有可见焦点，并能完成月份与日期的切换

#### Scenario: 分享单日页

- **WHEN** 单日页的链接被分享到支持 Open Graph 的平台
- **THEN** 平台可读取该日的标题、描述和照片预览信息

### Requirement: GitHub Pages 子路径兼容

展示页 SHALL 作为纯静态资源部署在 GitHub Pages 的项目子路径下运行，不得依赖服务端路由或绝对根路径。页面之间的跳转、数据请求和照片请求 MUST 使用相对路径或基于部署基路径解析，深链接在直接访问时仍能打开。

#### Scenario: 项目子路径部署

- **WHEN** 站点部署在 `https://example.github.io/photo-calendar/`
- **THEN** 月历页、单日页、`data/calendar.json` 与照片资源均从该子路径正确加载，不请求域名根路径下的资源

#### Scenario: 直接打开深链接

- **WHEN** 访客直接访问部署后的 `day.html?date=2026-11-08`
- **THEN** 页面正确打开该日期，不依赖先访问首页或服务端重写
