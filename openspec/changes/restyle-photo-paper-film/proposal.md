# Proposal

## Why

展示端已经有温暖、克制的纸张气质，但月历与单日页仍像两个不同的产品：月历是浅色纸张，单日页固定为深色；日期格更像普通卡片，缺少「翻开一张照片」的触感。编辑器也仍偏向常规后台工具，与照片、胶片的语义没有形成统一记忆点。现在功能与发布链路已经稳定，适合把视觉语言收拢成一套可被识别的体验。

## What Changes

- 展示端引入「相纸 / 拍立得」视觉语言：月历日期格、单日主图、无照片寄语都使用纸边、相纸阴影、胶带/日期印章等元素，照片本身仍是绝对视觉主体。
- 展示端建立统一的浅色/深色主题：月历与单日页共享同一套 token，按系统 `prefers-color-scheme` 同步切换，不再出现月历浅色、单日页固定深色的割裂；两套主题都保持相纸质感与 WCAG AA 对比度。
- 深色模式不是简单反色：浅色为奶油相纸与暖墨，深色为暗房/黑色相纸与暖白照片框，保留同一层级与可读性。
- 编辑器改为「胶片 / 暗房工作台」视觉：暗房底色、琥珀安全灯强调色、胶片齿孔/接触印样（contact sheet）网格、帧号与更克制的元数据排版，覆盖图库、导入、详情、设置与弹窗。
- 视觉改造只调整样式与必要的展示性 DOM 包裹，不改变数据契约、导入/生成/发布行为、命令接口或路由；保留现有键盘、axe、移动端与减少动态效果能力。
- 增加两套主题的视觉/可访问性回归测试与截图检查，确保相纸装饰不遮挡照片、文字或交互控件。

## Capabilities

### New Capabilities

- `editor-film-interface`: 编辑器各视图的胶片/暗房视觉语言、接触印样布局、状态与焦点呈现，以及视觉可访问性约束。

### Modified Capabilities

- `calendar-display`: 展示端的相纸/拍立得视觉语言，以及月历与单日页一致、可自动切换的浅色/深色主题要求。

## Impact

- 代码：`apps/web/src/styles.css`、`apps/web/src/month.ts`、`apps/web/src/day.ts`、`apps/web/src/doodle.ts`、两个 HTML 页面；`apps/editor/src/styles.css` 及 `apps/editor/src/main.ts` 中少量展示性 class/包裹；Web 与编辑器的视觉测试。
- 依赖：不引入新的运行时依赖；继续使用原生 CSS、现有字体栈与 css-doodle。
- 外部系统：无变化。数据契约、照片处理、DeepSeek、Git 发布及 GitHub Pages 工作流均不改动。
- 兼容性：面向现代桌面与移动浏览器；编辑器仍为桌面 Tauri 应用。
- 风险：相纸旋转/阴影可能造成溢出或触控区变化；深色模式下照片边框与文字对比度需要逐项校验。
