# Design

## Context

见 `proposal.md`。当前展示端用一份 `apps/web/src/styles.css` 同时服务月历与单日页：`:root` 固定 `color-scheme: light`，月历使用奶油纸色，单日页通过 `.day-page` 与 `--night` 固定为深色；两页没有共享的主题切换。编辑器也是独立的浅色后台样式，只有侧栏使用深色。两端都已具备完整的语义结构、响应式与可访问性测试，因此本次改造应集中在 token、CSS 与少量展示性包裹，不触碰数据与命令层。

设计假设：

- 「light/dark 保持统一」按系统 `prefers-color-scheme` 实现，不新增手动主题切换器；两页共享同一套主题语义，避免再出现单日页固定深色。若后续需要手动切换，可在现有 token 上增加 `data-theme` 覆盖，不需要重做结构。
- 编辑器采用单一「暗房/胶片」主题，不要求跟随系统浅色；胶片语义本身以暗房为视觉基础，浅色编辑器不在本次范围。
- 不引入新字体、图片纹理、动画库或运行时依赖。相纸与胶片质感用 CSS 渐变、边框、阴影、伪元素和现有字体栈完成。

## Goals / Non-Goals

**Goals:**

- 用一套可命名的语义 token 让月历、单日页、无照片回退在浅色与深色下都像同一本相册。
- 让照片在「相纸框」中仍是绝对主体，装饰只强化触感，不遮挡或改变信息层级。
- 让编辑器的所有视图共享暗房工作台语言，并用接触印样/帧号组织照片，而不是逐页换皮。
- 在 320–1920px、两套主题、减少动态效果与 axe 检查下保持现有质量标准。

**Non-Goals:**

- 不改变数据契约、照片处理、EXIF 白名单、DeepSeek 请求、Git 发布、设置存储或命令接口。
- 不新增手动主题开关、主题跟随账号同步、编辑器浅色主题。
- 不做照片精修、滤镜、裁剪、相框图片素材或 3D 效果。
- 不重写页面结构、路由、月历算法或编辑器状态机；展示性包裹保持在最小范围。

## Decisions

### 1. 展示端使用单层语义 token + `prefers-color-scheme` 覆盖

- 在 `apps/web/src/styles.css` 中把颜色、纸张、相纸框、阴影、胶带、舞台背景收敛为语义变量：`--paper`、`--paper-deep`、`--ink`、`--muted`、`--line`、`--accent`、`--frame`、`--frame-ink`、`--tape`、`--stage`、`--shadow` 等。
- `:root` 定义浅色值并声明 `color-scheme: light dark`；`@media (prefers-color-scheme: dark)` 只覆盖 token，不复制组件规则。月历与单日页都消费同一组 token，`.day-page` 不再固定深色。
- 深色不是反色：背景转为暖黑/暗房色，相纸框仍保留暖白纸边，照片与纸边的对比更强；正文使用暖白，强调色改为琥珀/砖红。
- `index.html` 与 `day.html` 各放两个 `meta[name="theme-color"]`，分别带 `media="(prefers-color-scheme: light)"` 与 `(prefers-color-scheme: dark)`；系统切换时浏览器主题色由媒体查询自动更新，无需 JS。
- 替代方案：用 JS 读写 `localStorage` 做手动主题。被否决：本次没有手动切换需求，增加状态、首屏闪烁与可访问性成本；系统偏好已能表达 light/dark 统一。替代方案：只做浅色相纸、深色单日页。被否决：正是当前割裂的来源。

### 2. 相纸效果用「纸边容器 + 伪元素」而不是图片素材

- 月历：日期格保持一个可点击 `<a>`，有照片时增加 `span.day-print` 包裹缩略图与日期章；无照片日期不创建 `day-print`，只留日期章与空白纸面。照片加载失败也移除 `day-print`，避免出现空白相纸。相纸白边、轻微旋转与阴影由 CSS 完成，胶带/打孔用 `::before`/`::after`，全部 `pointer-events: none`、`aria-hidden` 语义（伪元素天然不进入可访问树）。
- 单日页：照片增加 `figure.photo-paper`（`img` + 可选的纸边标记），文案仍放在 `.day-copy` 的独立纸卡中；照片不裁切、不加遮罩，`object-fit: contain` 保留。无照片页把 `.fallback-copy` 包成明信片纸卡，图样继续作为背景。
- 日期章使用现有日期/星期文本，不引入装饰性重复文本；照片 `alt` 与文案 `textContent` 继续由现有逻辑提供。
- 旋转只作用于容器内的相纸，使用 `transform` 不改变布局；容器 `overflow: clip`/`hidden` 限制在格子内，避免横向滚动。移动端把旋转收敛到 0，保证触控区与网格稳定。
- 替代方案：用 PNG 相纸/胶带纹理。被否决：增加资源体积、暗色适配与高清屏成本；CSS 已足够表达纸边和阴影。替代方案：给每张照片套真实 `<figure>` + `<figcaption>` 复制文案。被否决：会造成重复可读文本和布局膨胀。

### 3. 深色主题用「暗房相册」而不是纯黑反色

- 浅色主题：奶油纸面、暖墨、砖红强调、相纸暖白边、柔和棕阴影。
- 深色主题：暖黑背景（接近暗房）、深棕纸面、暖白正文、琥珀强调、相纸框保持暖白以托住照片；日期章和分隔线使用低对比暖灰，避免纯黑纯白刺眼。
- 相纸框在两种主题下都使用 `--frame`/`--frame-ink`，而不是复用页面 `--paper`；这样暗色页面中的照片仍有「实体相纸」的边界，但信息区不会被误读为纸框。
- 背景纹理用低透明度重复渐变/径向渐变实现，不使用 `filter: noise` 或大图；避免移动端合成开销与主题切换闪烁。

### 4. 编辑器采用暗房接触印样语言，CSS 为主、DOM 钩子为辅

- `apps/editor/src/styles.css` 重建 token：`--bg` 暖黑、`--panel` 深棕、`--ink` 暖白、`--muted` 灰褐、`--accent` 琥珀、`--safelight` 暗红、`--film-edge` 齿孔色。侧栏像胶片罐/暗房墙面，主区像接触印样台。
- 图库 `.photo-grid` 增加接触印样容器语义：CSS counter 生成帧号（`aria-hidden` 伪元素），日期与文案仍由现有 DOM 提供；卡片使用相纸边、底片孔和轻阴影，不改变 `button.photo-card` 的可点击语义。
- 导入 `.draft-list`/`.draft-card` 呈现为一条胶片条：上下齿孔用重复渐变，草稿预览像单帧印样；日期、冲突、文案、保存按钮保持原有顺序与可操作性。
- 详情把 `.detail-image` 做成放大底片/印样框，`.detail-form` 像暗房记录卡；设置表单与 `secret-box` 像实验室标签页。仅增加 class/包裹，不改变字段、按钮与命令绑定。
- 状态色：待发布用琥珀、错误用暗红、成功用低饱和绿；同时保留文字/图标/边框。暗房主题的正文与表单对比度按 WCAG AA 校验。
- 替代方案：编辑器纯 CSS 换色、不加结构钩子。被否决：接触印样/帧号/胶片条需要容器与伪元素计数，纯换色无法形成识别度。替代方案：引入组件库/图标包。被否决：项目坚持原生 DOM 与最小依赖。

### 5. 动效、响应式与可访问性作为验收门槛

- 相纸 hover 只做 1–2px 抬升/阴影变化；不支持 `hover` 的设备不做位移。主题切换用短过渡，`prefers-reduced-motion: reduce` 下全局关闭。
- 相纸装饰使用 `pointer-events: none`；交互仍落在原有日期格/按钮上。日期格保持最小 44×44，移动端网格不出现横向滚动。
- 单日页相纸框的宽度用 `min()` 限制，照片 `max-width: 100%`，避免旋转后溢出；编辑器保持最小宽度 720px 的既有约束。
- 所有新装饰不进入可访问树；焦点样式在相纸、暗色背景和图片上都有高对比外框。两套主题分别跑 axe。

### 6. 测试与视觉检查

- Web 单元测试保持现有 DOM 断言；新增/扩展 Playwright：
  - `emulateMedia({ colorScheme: 'light' | 'dark' })` 下检查月历与单日页使用同一主题 token，深色下 `--paper` 与浅色不同。
  - 检查两页 `meta[name=theme-color]` 的 media 组合，及 `color-scheme` 为 `light dark`。
  - 375px/1440px 无横向滚动；日期格最小触控区；相纸装饰不拦截点击。
  - 浅色/深色分别跑 axe；减少动态效果下无过渡。
- 编辑器：既有 Vitest/jsdom 交互测试作为行为回归；新增对胶片容器 class/帧号结构的断言（不依赖像素），并用 Tauri 开发窗口在浅色/深色 OS 下人工截图检查。axe 继续在 jsdom 主视图运行，补一条暗房主题下的结构检查。
- 视觉验收以截图为准，不引入像素快照基线，避免字体渲染差异导致 CI 脆弱；截图作为 PR/验收附件记录。

### 7. 反馈修正：等高行与照片贴合

- 月历使用固定 `grid-auto-rows`（桌面 118px、移动端 64px）而不是让内容决定行高。相纸/缩略图的尺寸变化不再改变行高；补位格与有照片格使用同一轨道。移动端仍以 44×44 为触控下限。
- 编辑器不再给照片套纸边：图库卡片改为暗房面板，缩略图左右无内边距；详情图片容器改为 `width: fit-content`、无 padding/背景边框，图片本身决定框的尺寸。这样「背景框」与照片同尺寸，且不会出现白色嵌套。
- 相纸/胶片语言仍保留在边框、帧号、日期标签与暗房材质上，但不再通过照片四周的纸白边表达。
- 替代方案：保留相纸白边但缩小。被否决：用户明确要求照片周围不嵌套白边；这属于视觉语义修正，不是尺寸微调。

## Risks / Trade-offs

- **相纸旋转/纸边导致溢出或触控区变化** → 只在容器内旋转，移动端取消旋转；用 Playwright 检查 `scrollWidth` 与日期格 bounding box。
- **深色相纸框与正文对比度不足** → 相纸框、页面背景、正文各自使用独立 token；两套主题分别跑 axe 与对比度抽查。
- **CSS 伪元素帧号/齿孔被辅助技术读出或干扰点击** → 伪元素不进入可访问树，装饰 `pointer-events: none`；帧号仅作视觉补充，日期文本仍是主信息。
- **编辑器暗房主题让长时间使用的可读性下降** → 避免纯黑纯白与高饱和红；正文对比度按 AA；设置/错误等高频文本优先可读性。
- **新增 DOM 包裹影响现有选择器/测试** → 保留 `.day-cell`、`.day-thumb`、`.day-photo`、`.photo-card`、`.draft-card` 等现有 class；新增包裹只加不换，先跑完整测试。
- **主题色 meta 与浏览器支持差异** → 使用两条 media meta 而非 JS；不支持 media 的浏览器只使用最后一条，不影响页面内容。
- **视觉改造被误认为功能变更** → 数据、命令、路由、文案生成与 Git 发布零改动；以现有单元/E2E/axe 全绿作为回归门槛。

## Migration Plan

1. 先落 token 与浅/深主题，保持现有 DOM，跑一轮 Web E2E 与 axe，确认没有布局/功能回归。
2. 再加相纸 DOM 包裹与 CSS，逐页（月历 → 单日 → 回退）检查移动端与两套主题。
3. 最后改编辑器 token 与接触印样/胶片条，逐视图截图检查；功能测试不改。
4. 若视觉回归不可接受，按文件 revert CSS/展示性包裹即可回到旧皮肤；无数据迁移、无发布链路变更。

## Open Questions

无。手动主题开关与编辑器浅色主题已明确列为非目标；若后续需要，可在同一 token 层增加覆盖机制。
