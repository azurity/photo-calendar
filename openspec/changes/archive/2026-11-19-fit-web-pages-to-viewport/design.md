# Design

## Context

对当前构建在 Chrome 下实测的页面高度：

| 页面 | 视口 | 内容高度 | 溢出 |
| --- | --- | --- | --- |
| 月历 2026-11（6 行） | 1440×900 | 1123 | 223 |
| 月历 2026-11 | 375×667 | 807 | 140 |
| 月历 2026-11 | 320×667 | 813 | 146 |
| 单日 2026-11-15 | 1440×900 | 1039 | 139 |
| 单日 2026-11-15 | 375×667 | 711 | 44 |
| 单日 120 字文案 | 1440×900 | 1241 | 341 |

月历由 `.site-header`、`.page-main`（月标题 + `.month-grid-wrap`，内含星期行与固定 118px/64px 行的网格）与 104px 高的 `.site-footer` 组成；`page-main` 的 56px 底部内边距也计入。日期格当前有 118px/64px 的固定 `grid-auto-rows` 和 `min-height`，无法压缩。

单日页由 `.day-header`、`.day-photo-stage`（flex:1，内部相纸 + 图片 + 白边文案）、`.day-navigation` 与 `.day-main` 的 48px 底部内边距组成；照片固定 `max-height: 64vh`，相纸白边文案高度可变；120 字文案会让相纸显著增高。

约束：日期格不小于 44×44；照片不裁切；文案不裁切；不出现横向滚动；长文案允许纵向滚动但不能靠 `overflow: hidden` 隐藏内容。项目仍为纯 CSS/原生 DOM，不引入 JS 布局测量。

## Goals / Non-Goals

**Goals:**

- 默认数据下，月历与常规单日页在 1440×900、1440×1000、375×667、320×667 不产生页面纵向滚动。
- 月历在 6 行月份下仍完整显示 30 个日期、星期行、月份导航与页脚（移动端短视口可用隐藏装饰页脚换空间）。
- 单日页在压缩照片高度后仍让照片是主体，日期、星期与手写文案完整可读。
- 超长文案、提示条或极小视口下允许正常纵向滚动，而不是裁切或嵌套滚动。

**Non-Goals:**

- 不保证 120 字文案、数据提示条或高度小于 667px 的视口完全不滚动。
- 不改变数据契约、路由、主题、相纸视觉或手写字体。
- 不引入 JS 的 `ResizeObserver`/滚动监听来动态计算高度。
- 不删除月历日期信息、单日文案或导航；页脚只在短视口隐藏。

## Decisions

### 1. 月历页改为视口高度 flex 链，网格行共享剩余高度

- `.month-page` 使用 `min-height: 100dvh`（带 `100vh` 回退）与纵向 flex；页头、页脚 `flex: none`。
- `.page-main` 改为 `flex: 1; min-height: 0; display: flex;`，`#app` 与 `.month-view` 继续传递 `flex: 1; min-height: 0; display: flex; flex-direction: column`。
- `.month-grid-wrap` 改为纵向 flex 且 `flex: 1; min-height: 0`；`.weekday-row` 固定；`.month-grid` 用 `flex: 1; min-height: 0; grid-auto-rows: minmax(78px, 1fr)`（移动端 `minmax(56px, 1fr)`），`.day-cell` 去掉固定 `min-height`，由行高撑开。
- 6 行月份在 1440×900 下：页头 60 + 月标题约 140 + 星期行 42 + 主区上下内边距约 24 + 页脚约 60，剩余约 574px，每行约 95px，高于 78px 下限；375×667 隐藏页脚后剩余约 386px，每行约 64px，高于 56px 下限。
- 4/5 行月份会得到更高的日期格（1fr 分配剩余空间），这是可接受的日历拉伸；缩略图随格子增大，不改变信息层级。
- 备选：用 `calc((100dvh - 固定高度) / 6)` 写死行高。被否决：月份可能是 4/5/6 行，固定除法会浪费空间或溢出。
- 备选：给 `.month-grid` 加 `overflow: auto` 内部滚动。被否决：用户要的是页面不滚动，内部滚动会造成更差的嵌套滚动体验。

### 2. 页脚在短视口隐藏，桌面保留紧凑页脚

- `.site-footer` 的上下 padding 从 24/36 收到约 16/20，桌面仍可见。
- `@media (max-height: 760px)` 下 `.site-footer { display: none; }`，为 375×667、320×667 的 6 行月历腾出约 60–100px；页脚只是装饰性句子，不影响日期、导航或可访问性主内容。
- 备选：保留页脚并把移动端行高压到 56px 以下。被否决：会牺牲日期格可触控面积。
- 备选：把页脚并入主区。被否决：会让月历主体与页脚争空间，且视觉层级更乱。

### 3. 单日页按视口收紧照片与垂直留白，长文案仍可滚动

- 桌面 `.day-photo` 的 `max-height` 从 `64vh` 收到 `min(52vh, 720px)`；`.day-photo-stage` padding-top 从 26px 收到 20px；`.day-navigation` margin-top 从 22px 收到 14px；`.day-main` 底部 padding 从 48px 收到 24px。1440×900 下照片约 468px、相纸约 670px，加上页头与导航约 850px，落入视口。
- 移动端 `.day-photo` 从 `min(44vh, 420px)` 收到 `min(38vh, 360px)`；stage padding 12px；navigation margin 12px；main padding 20px。375×667 下常规文案约 590px 总高。
- 不把相纸设为 `overflow: hidden`，也不让图片 flex-shrink 与文案宽度互相反馈；照片高度用可预测的视口比例，长文案自然把页面撑高并允许纵向滚动。
- 备选：用 flex 让图片在剩余空间内自动收缩。被否决：相纸宽度由照片宽度决定，照片缩小会让文案换行更多、白边更高，产生高度反馈；固定上限更稳定。
- 备选：压缩文案字号或隐藏星期。被否决：会牺牲可读性与信息完整性，优先调整照片与留白。

### 4. 只收缩，不裁切；失败时允许页面滚动

- 不给 `html`/`body` 加 `overflow: hidden`；只通过 flex 分配与最小高度约束达成不滚动。若内容超过最小高度（120 字文案、提示条、低于 667px 的视口），页面保持正常纵向滚动，所有文字与照片完整。
- 横向溢出继续由 `body { overflow-x: hidden }` 兜底；不新增内部滚动容器。
- `100dvh` 前写 `100vh` 作为不支持动态视口的回退；不使用 JS。

### 5. 测试与视觉验收

- 在 `calendar.spec.ts` 增加页面高度断言：`document.documentElement.scrollHeight <= innerHeight + 1` 且 `scrollWidth <= innerWidth`，覆盖 2026-11（6 行）与 2026-11-15（常规文案）在 1440×900、375×667、320×667 的组合。
- 120 字文案测试只断言「无横向滚动、文字与照片不裁切、文案文本完整」，不强制要求滚动（1440×1000 可能刚好放下）；若实际溢出，允许 `scrollHeight > innerHeight`。
- 现有月历等高行、无横向滚动、主题与 axe 测试保持通过；若固定行高断言需要按 1fr 调整，只改断言实现，不放宽「所有行等高」。
- 视觉验收截图：月历与单日页在 1440×900、375×667 的浅色/深色，确认日期格可读、照片主体与手写文案未被压扁。

## Risks / Trade-offs

- **4/5 行月份日期格被拉得很高** → 缩略图随格放大，仍保持接触印样；如视觉上过松，可在后续单独限制最大行高（本次不处理）。
- **移动端隐藏页脚** → 页脚是装饰性句子，不影响主体；在文档与视觉验收中记录。
- **短视口或提示条下仍可能滚动** → 规范允许；用最小行高/最小照片高度避免裁切，测试覆盖无提示条的正常场景。
- **照片在桌面变小** → 从 64vh 降到 52vh，仍占视口一半以上；用截图确认仍是视觉主体。
- **flex 高度链遗漏 `min-height: 0` 导致内容溢出** → 逐层设置并在 1440×900/375×667 实测 `scrollHeight`。
- **`dvh` 兼容性** → 先声明 `100vh` 回退，再声明 `100dvh`；不支持时退回视口高度。
- **固定行高测试失效** → 等高行仍成立；测试从具体像素改为比较行高相等，不降低质量门槛。

## Migration Plan

1. 先改月历页高度链与网格行，跑 Playwright 视口断言，确认 1440×900/375×667/320×667 无纵向滚动。
2. 再改单日页照片高度与留白，逐视口检查常规文案与 120 字文案。
3. 调整/新增 Playwright 断言与视觉截图。
4. 更新 `docs/visual-language.md` / `docs/visual-acceptance.md` 的视口策略说明。
5. 回滚：仅涉及 `styles.css` 与 Web 测试/文档，按文件 revert 即可；无数据或路由变更。
