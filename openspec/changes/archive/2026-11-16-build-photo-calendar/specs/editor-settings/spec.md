# Spec Delta

## Purpose

把编辑器的外部依赖集中到一处可理解、可验证的配置里：DeepSeek 的访问方式、站点 Git 仓库与发布选项。密钥必须安全保存，错误配置必须能指出具体问题，而不是等到导入或发布时才以晦涩方式失败。

## ADDED Requirements

### Requirement: 设置界面与可配置项

编辑器 SHALL 提供统一的设置界面，至少允许配置：DeepSeek API Key、API Base URL、模型名、Git 远端地址、发布分支、本地工作副本路径、自动发布开关与线上站点地址。界面 SHALL 为每个字段提供说明、当前值和保存状态。

#### Scenario: 打开设置

- **WHEN** 用户从主界面进入设置
- **THEN** 设置页显示 DeepSeek 与 Git 两组配置，已保存的值可读，密钥以掩码呈现

#### Scenario: 修改模型

- **WHEN** 用户把模型名从 `deepseek-flash` 改为另一个可用的 DeepSeek 模型并保存
- **THEN** 后续文案生成使用新模型，已有条目不被重新生成

#### Scenario: 配置自动发布

- **WHEN** 用户开启「保存后自动发布」并保存设置
- **THEN** 之后每次成功保存照片或文案都会触发一次发布；关闭时只标记待发布，由用户手动发布

### Requirement: API Key 的安全存储

DeepSeek API Key MUST 存储在操作系统钥匙串或等效的安全凭据存储中，MUST NOT 以明文写入应用配置文件、仓库、日志、崩溃报告或界面可复制的诊断信息。设置界面 SHALL 仅显示掩码或末四位，并提供替换与清除操作。

#### Scenario: 保存密钥

- **WHEN** 用户输入 API Key 并保存
- **THEN** 密钥进入系统钥匙串，应用配置文件中只保留「已配置」状态或引用标识，不出现密钥明文

#### Scenario: 再次打开设置

- **WHEN** 用户重新打开设置页
- **THEN** API Key 字段显示为掩码，不显示完整密钥，用户无法通过界面或日志还原密钥

#### Scenario: 清除密钥

- **WHEN** 用户点击清除 API Key 并确认
- **THEN** 系统钥匙串中的密钥被删除，文案生成入口提示需要重新配置

#### Scenario: 日志与诊断脱敏

- **WHEN** 应用记录 DeepSeek 请求错误或导出诊断信息
- **THEN** 日志和诊断中不包含 API Key，认证头被替换为掩码

### Requirement: 连接测试与错误诊断

设置页 SHALL 提供 DeepSeek 与 Git 的连接测试，并在合理超时内返回结果。DeepSeek 测试 MUST 使用最小请求验证密钥与模型可用性；Git 测试 MUST 验证远端可访问、分支可解析。失败时 SHALL 显示具体原因与修复建议，例如密钥无效、模型不存在、网络超时、仓库无权访问或分支不存在。

#### Scenario: DeepSeek 测试成功

- **WHEN** 用户填入有效 API Key 并点击「测试连接」
- **THEN** 编辑器在超时时间内显示连接成功与当前模型名

#### Scenario: DeepSeek 密钥无效

- **WHEN** 测试请求返回 401 或 403
- **THEN** 编辑器显示密钥无效或无权限，并保留用户输入以便修改，不把失败当作已保存状态

#### Scenario: Git 仓库无权限

- **WHEN** Git 测试因认证失败或仓库不可访问而失败
- **THEN** 编辑器显示权限或地址问题，并提示检查系统 Git 凭据或 SSH Agent

#### Scenario: 测试超时

- **WHEN** 连接测试在配置的超时时间内没有响应
- **THEN** 编辑器报告超时，不无限等待，也不把未验证的配置标记为可用

### Requirement: 非敏感配置的持久化

除密钥外的设置 SHALL 保存到平台标准的应用配置目录，并在应用重启后恢复。配置写入 MUST 是原子的；配置文件损坏时，应用 MUST 以安全默认值启动并提示用户重新配置，不得覆盖损坏文件之外的用户数据。

#### Scenario: 重启后恢复

- **WHEN** 用户保存仓库地址、分支与模型后重启应用
- **THEN** 设置页和后续操作仍使用这些值

#### Scenario: 配置文件损坏

- **WHEN** 应用启动时发现配置文件不是合法 JSON
- **THEN** 应用以空配置启动，保留损坏文件副本或备份，提示用户检查设置，不删除照片数据

#### Scenario: 写入失败

- **WHEN** 保存配置时磁盘只读或空间不足
- **THEN** 界面显示保存失败，内存中的旧值与磁盘上的旧配置保持一致

### Requirement: 配置值校验

编辑器 MUST 在保存前校验配置格式：API Base URL 与站点地址 MUST 为 `http` 或 `https` URL；模型名 MUST 非空；Git 远端 MUST 为可解析的 HTTPS 或 SSH 地址；分支名 MUST 符合 Git 引用格式；工作副本路径 MUST 是绝对路径。非法值 MUST 被拒绝并指出具体字段与原因。

#### Scenario: 非法的仓库地址

- **WHEN** 用户填写 `not-a-url` 作为 Git 远端
- **THEN** 保存被拒绝，字段旁显示「请输入 HTTPS 或 SSH 形式的仓库地址」

#### Scenario: 非法分支名

- **WHEN** 用户填写包含空格或以 `-` 开头的分支名
- **THEN** 保存被拒绝并说明分支名不合法，不把该值传给 Git

#### Scenario: 相对工作副本路径

- **WHEN** 用户填写 `./site` 作为工作副本路径
- **THEN** 编辑器要求使用绝对路径，或明确解析为绝对路径后展示最终路径再保存

### Requirement: 首次运行与配置缺失

首次运行且尚未配置时，编辑器 SHALL 展示可跳过的引导，说明照片导入可离线使用，而文案生成与发布需要配置。缺少某项配置时，相关功能 MUST 以禁用状态或明确提示呈现，不得在点击后才以崩溃或空白错误结束。

#### Scenario: 首次启动

- **WHEN** 用户第一次打开编辑器，配置目录为空
- **THEN** 界面显示引导与设置入口，照片导入和本地浏览仍然可用

#### Scenario: 未配置 API Key 时使用导入

- **WHEN** 用户导入照片但尚未配置 API Key
- **THEN** 照片可保存到本地，文案生成按钮提示先配置密钥，不发出请求

#### Scenario: 未配置 Git 时保存

- **WHEN** 用户保存照片但尚未配置 Git 仓库
- **THEN** 条目保存在本地并标记为待发布，发布入口提示先完成仓库配置

### Requirement: 跨平台运行与平台集成

编辑器 MUST 能在 Windows 10/11 与主流 Linux 桌面环境运行，并使用平台标准的文件选择器、应用配置目录与安全凭据存储。Windows 与 Linux 上保存的照片、配置与 Git 工作副本 MUST 使用各自平台可写的路径，不得依赖 Unix 专有路径或 shell 特性。

#### Scenario: Windows 运行

- **WHEN** 用户在 Windows 11 上安装并启动编辑器
- **THEN** 应用能打开原生文件选择器、保存照片、读取系统钥匙串并调用系统 Git

#### Scenario: Linux 运行

- **WHEN** 用户在 Linux 桌面环境启动编辑器
- **THEN** 应用遵循 XDG 配置目录、使用可用的 Secret Service 或等效钥匙串，并能完成导入与发布流程

#### Scenario: 平台不支持钥匙串

- **WHEN** Linux 环境没有可用的 Secret Service
- **THEN** 编辑器明确提示无法安全保存密钥，要求使用会话内临时密钥或先配置凭据服务，不得退化为明文保存

### Requirement: 设置变更的影响控制

修改 Git 仓库、分支或工作副本路径时，编辑器 SHALL 说明影响范围，并在存在待发布改动或正在进行的发布时阻止立即切换。配置变更 MUST NOT 删除本地已保存的照片或历史数据。

#### Scenario: 有待发布改动时更换仓库

- **WHEN** 本地存在待发布条目，用户尝试切换到另一个 Git 仓库
- **THEN** 编辑器提示先发布或放弃待发布改动，或保留原仓库配置，不静默切换导致改动无法推送

#### Scenario: 更换工作副本路径

- **WHEN** 用户把工作副本路径改为一个新目录
- **THEN** 编辑器验证新路径可用，原目录中的用户数据不被自动删除，并在下次发布时按新路径克隆或使用仓库

### Requirement: 中文界面与可访问性

编辑器界面 SHALL 以中文呈现，设置项、错误信息、按钮和状态文本 MUST 使用一致的中文术语。所有设置控件 SHALL 可通过键盘操作，错误信息 MUST 与对应字段关联，并被辅助技术读出。

#### Scenario: 键盘完成配置

- **WHEN** 用户仅使用键盘导航设置页
- **THEN** 可以依次聚焦所有字段、触发连接测试、保存或取消，且焦点顺序合理

#### Scenario: 错误可被读出

- **WHEN** 某个字段校验失败
- **THEN** 该字段被标记为无效，错误文本通过可访问描述与字段关联，屏幕阅读器可读出
