# Spec Delta

## Purpose

为每一天的照片生成一句真正与画面和日期有关的文案：不是通用模板，而是能让人重新看见当天光景、并愿意走出门去看看世界的文字。同时保证「换一句」时不会立刻得到与上一版相同的话。

## ADDED Requirements

### Requirement: 基于照片与日期的生成

用户请求为某天生成文案时，编辑器 SHALL 将处理后的照片画面、该日期的日历特征（公历日期、星期、可识别的节日/节气等）与固定文风要求一并发送给 DeepSeek 视觉模型，并将返回的中文文本作为该条目的候选文案。默认模型为 `deepseek-flash`，请求 MUST 使用 OpenAI 兼容的 Chat Completions 图片输入格式。

#### Scenario: 为照片生成文案

- **WHEN** 用户在某条有照片的条目上点击「生成文案」
- **THEN** 编辑器发送包含该照片与日期信息的请求，并在请求成功后将返回文本显示为可编辑的候选文案

#### Scenario: 没有照片时

- **WHEN** 用户尝试为一个没有照片的日期生成文案
- **THEN** 编辑器阻止请求并提示先添加照片，不发送空图片或不完整的请求

#### Scenario: 发送可识别的日期特征

- **WHEN** 目标日期是 10 月 1 日
- **THEN** 请求上下文中包含国庆节这一日期特征，供模型在合适时自然引用

### Requirement: 文案内容与文风

生成的文案 MUST 为中文，长度 MUST 在 15–120 个汉字之间，通常为一至两句。文案 MUST 与照片中可辨认的内容相关，并体现感性、巧思、引导探索世界或呈现世界美好的意味；在有可靠日期特征时 SHOULD 自然呼应节日、节气或当天的特别之处。文案 MUST NOT 是脱离画面的通用祝福、空洞排比或可套用于任意照片的模板。

#### Scenario: 文案呼应画面

- **WHEN** 照片中有一把面向街道的旧椅子
- **THEN** 文案至少包含与椅子、街道、等待或出发等画面元素相关的具体意象，而不是「美好的一天」这类通用表述

#### Scenario: 文案呼应日期

- **WHEN** 目标日期是中秋节，且照片是夜晚的街景
- **THEN** 文案可以在不牵强的前提下呼应团圆、月色或秋夜，同时仍与照片中的街景相关

#### Scenario: 普通日期

- **WHEN** 目标日期没有被识别的节日或节气
- **THEN** 文案不编造节日，仍基于画面与星期等信息写出当天独有的感受

### Requirement: 引用诗句与名言

文案 MAY 在自然契合时引用诗句、名言或民谚，但引用 MUST 与画面和日期相关，且作者、出处或原文 MUST 准确。无法确认出处或原文时 MUST NOT 编造引用，也不得把网络流行语伪装成名人名言。

#### Scenario: 恰当引用

- **WHEN** 照片是秋日落叶，而当天又接近可识别的节气
- **THEN** 文案可以引用与秋日相关的、出处准确的短句，并保持整体仍像一句自然的描述

#### Scenario: 无法确认出处

- **WHEN** 模型想引用一句无法确认作者或出处的「名言」
- **THEN** 最终文案不包含该引用，改用不依赖出处的原创描述

### Requirement: 刷新去重

用户对同一条目请求「换一句」时，新文案在去除空白、标点差异与首尾引号后 MUST 与刷新前的文案不同。若模型返回与上一版实质相同的内容，编辑器 MUST 自动重试，最多再请求两次；三次结果都重复时，MUST 保留原文案并报告刷新失败，不得静默接受重复内容。

#### Scenario: 刷新得到不同文案

- **WHEN** 用户点击「换一句」，模型返回与上一版明显不同的文案
- **THEN** 候选文案更新为新内容，旧文案在被保存前仍可恢复

#### Scenario: 仅标点不同

- **WHEN** 模型返回的新文案与上一版只有末尾句号、空格或引号差异
- **THEN** 编辑器判定为重复并自动重试，不把该结果当作有效刷新

#### Scenario: 连续重复

- **WHEN** 三次请求返回的文案都与刷新前重复
- **THEN** 编辑器保留刷新前的文案，显示「本次没有生成新的文案」并允许稍后重试

#### Scenario: 不要求历史全局去重

- **WHEN** 新文案与更早的某一版相同，但不同于紧邻的上一版
- **THEN** 编辑器接受该文案，不因历史版本而拒绝

### Requirement: 日期特征计算

编辑器 SHALL 从本地日期特征库计算目标日期的公历节日、可识别的农历节日与二十四节气，并将结果随请求发送。日期特征 MUST 按目标日期的日历语义计算，不得按请求发生时间或 UTC 日期推断；无法确定或超出支持范围时 MUST 明确标记为「无已知特征」，不得猜测。

#### Scenario: 公历节日

- **WHEN** 目标日期为 2026-01-01
- **THEN** 请求上下文包含元旦这一特征

#### Scenario: 农历节日

- **WHEN** 目标日期对应农历正月初一
- **THEN** 请求上下文包含春节这一特征，且不因公历月份相同而误判为其他节日

#### Scenario: 超出日期特征库范围

- **WHEN** 目标年份超出本地特征库可可靠计算的范围
- **THEN** 请求上下文标记为无已知特征，模型不得自行编造该年的节日或节气

### Requirement: 请求结果校验

编辑器 MUST 对模型返回做去空白、去除包裹性引号与 Markdown 标记的规范化处理，并校验结果非空、为中文、长度合规、不是多段排版内容。校验失败时 MUST 将本次结果视为失败并按刷新规则重试；重试仍失败时保留原文案并报告原因。

#### Scenario: 返回空内容

- **WHEN** 模型返回空字符串或只有空白
- **THEN** 编辑器不把空内容写入条目，显示生成失败并允许重试

#### Scenario: 返回 Markdown 或多段文本

- **WHEN** 模型返回带标题、列表或代码块的整段内容
- **THEN** 编辑器拒绝该结果，或在可安全提取为单一文案时按规则规范化，否则重试并最终报错

#### Scenario: 返回超长文本

- **WHEN** 模型返回超过 120 个汉字的文案
- **THEN** 编辑器将其视为不合规结果，不直接写入条目

### Requirement: 失败处理与可恢复性

文案生成失败时，编辑器 MUST 保留该条目原有的文案和照片，不得写入半成品，也不得用固定模板静默替代。错误信息 SHALL 区分未配置 API Key、认证失败、额度或频率限制、网络超时、服务端错误与内容安全拒绝，并给出可操作的下一步。

#### Scenario: 未配置 API Key

- **WHEN** 用户在没有配置 DeepSeek API Key 时请求生成文案
- **THEN** 编辑器提示前往设置配置密钥，不发出网络请求，也不修改现有文案

#### Scenario: 认证失败

- **WHEN** DeepSeek 返回 401 或 403
- **THEN** 编辑器提示 API Key 无效或无权限，保留原文案，并提供打开设置的动作

#### Scenario: 频率限制

- **WHEN** DeepSeek 返回 429
- **THEN** 编辑器提示请求过于频繁，展示服务端建议的等待时间（若有），保留原文案并允许稍后重试

#### Scenario: 网络中断

- **WHEN** 请求超时或网络不可达
- **THEN** 编辑器提示网络问题，保留原文案，用户可在恢复网络后重试而不必重新导入照片

#### Scenario: 内容安全拒绝

- **WHEN** DeepSeek 因图片或提示触发内容安全策略而拒绝
- **THEN** 编辑器说明该图片未能生成文案，保留原状态，不循环重试同一被拒绝的请求

### Requirement: 生成元数据与手动文案

每次成功生成 SHALL 在条目中记录使用的模型名、提示词版本与生成时间。文案 MUST 可被用户手动编辑；被标记为手动编辑的文案在用户再次请求生成或刷新前 MUST NOT 被自动覆盖，编辑器 SHALL 在覆盖前明确确认。

#### Scenario: 记录生成信息

- **WHEN** 一次文案生成成功并保存
- **THEN** 条目中记录模型、提示词版本和生成时间，供后续排查与展示使用

#### Scenario: 保护手动文案

- **WHEN** 用户手动修改过文案后再次点击「换一句」
- **THEN** 编辑器先提示将覆盖手动内容，只有用户确认后才发送生成请求

#### Scenario: 手动文案不被后台覆盖

- **WHEN** 条目文案被标记为手动编辑，且用户没有发起生成或刷新
- **THEN** 编辑器不会因定时任务、重新打开或保存其他条目而自动改写该文案

### Requirement: 请求隐私与并发控制

发送给 DeepSeek 的图片 MUST 为完全去除元数据的展示副本（即使发布主图保留了拍摄时间、镜头或曝光白名单字段，也不得随请求发送），长边不超过 1568 像素且体积不超过 2 MiB；请求 MUST NOT 包含照片的本地路径、GPS 坐标、设备序列号或其他不必要的个人信息。同一条目同一时间 MUST 只允许一个生成请求；用户离开或取消时，迟到的响应不得覆盖用户之后的操作。

#### Scenario: 发送压缩副本

- **WHEN** 用户用一张 6000×4000、带 GPS 与镜头/曝光 EXIF 的原始照片生成文案
- **THEN** 发送的图片不含任何 EXIF（包括发布主图保留的时间/镜头/曝光白名单）与 GPS，且长边不超过 1568 像素、体积不超过 2 MiB

#### Scenario: 并发点击生成

- **WHEN** 用户连续点击两次「生成文案」
- **THEN** 编辑器只发出一个请求，第二次点击被忽略或提示正在生成

#### Scenario: 取消后响应迟到

- **WHEN** 用户取消生成并编辑了文案，之前发出的请求随后返回
- **THEN** 迟到响应不会覆盖用户正在编辑的内容，也不会自动保存
