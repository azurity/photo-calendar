# Spec Delta

## Purpose

让编辑器把本地照片与文案安全地发布到站点仓库，并借助 GitHub Pages 的推送构建让线上日历自动更新。发布过程必须以不丢失数据、不强推、不泄露凭据为前提，并在网络或权限失败时给出可恢复的路径。

## ADDED Requirements

### Requirement: 仓库配置与连接校验

编辑器 SHALL 允许配置站点仓库的远端地址、发布分支与本地工作副本路径，并在保存前校验远端可访问、分支存在。远端地址 MUST 支持 HTTPS 与 SSH 形式；编辑器 MUST NOT 将访问令牌写入配置文件或仓库。

#### Scenario: 配置有效的仓库

- **WHEN** 用户填写可访问的 HTTPS 仓库地址与已存在的 `main` 分支
- **THEN** 连接测试成功，编辑器显示远端 HEAD 与工作副本状态，并允许保存配置

#### Scenario: 分支不存在

- **WHEN** 用户填写的分支在远端不存在
- **THEN** 编辑器报告该分支无法解析，不开始克隆或写入，并保留用户已填写的其他设置

#### Scenario: 地址包含明文凭据

- **WHEN** 用户粘贴的仓库 URL 形如 `https://user:token@host/repo.git`
- **THEN** 编辑器提示凭据不应出现在 URL 中，并在界面与日志中以掩码显示该地址

### Requirement: 工作副本准备

本地工作副本不存在时，编辑器 SHALL 将其克隆到配置路径；已存在时，MUST 校验 `origin` 与配置的远端一致、当前分支与配置分支一致。校验失败或工作副本包含与发布无关的本地修改时，编辑器 MUST 停止写入并说明冲突，不得覆盖或丢弃用户已有的改动。

#### Scenario: 首次发布时克隆

- **WHEN** 用户首次发布，且配置的工作副本路径不存在
- **THEN** 编辑器从配置的远端克隆仓库到该路径，检出配置分支，然后继续本次发布

#### Scenario: 远端不匹配

- **WHEN** 工作副本的 `origin` 指向另一个仓库
- **THEN** 编辑器停止发布，明确显示现有远端与期望远端，要求用户确认或更换工作副本路径

#### Scenario: 存在无关的未提交修改

- **WHEN** 工作副本中存在不在 `data/calendar.json` 与 `data/photos/` 范围内的未提交修改
- **THEN** 编辑器停止发布，列出这些文件，不暂存、不提交、不清理它们

### Requirement: 发布前同步远端

每次写入或推送前，编辑器 SHALL 获取远端最新状态。远端领先且本地没有未推送提交时，MUST 先快进到远端；双方都有新提交时，MUST 停止并报告分叉，不得自动强推、丢弃本地提交或静默变基。

#### Scenario: 远端有新提交

- **WHEN** 发布前 fetch 发现远端分支比本地领先，且本地没有待推送提交
- **THEN** 编辑器快进本地分支到远端，然后继续写入与提交

#### Scenario: 本地与远端分叉

- **WHEN** 本地存在未推送提交，同时远端也有新的提交
- **THEN** 编辑器停止发布，保留本地提交，并提示用户先手动同步或选择放弃本地提交，绝不执行 `push --force`

#### Scenario: 网络不可用

- **WHEN** 发布前 fetch 因网络错误失败
- **THEN** 编辑器不进入写入流程，保留本地待发布数据，并提示稍后重试

### Requirement: 受控的提交范围

编辑器提交时 MUST 只暂存 `data/calendar.json` 与 `data/photos/` 下的新增、修改和删除，并 MUST 使用能说明本次变更的提交信息。任何 API Key、访问令牌、配置文件、构建产物或用户目录中的其他文件 MUST NOT 进入提交。

#### Scenario: 提交照片与数据

- **WHEN** 用户新增一张照片并发布
- **THEN** 提交只包含更新后的 `data/calendar.json` 与该照片的主图、缩略图，以及被替换的旧资源的删除

#### Scenario: 工作区存在其他改动

- **WHEN** 工作副本中同时存在用户手动修改的网页源码
- **THEN** 该源码文件不进入本次提交，仍以未提交状态保留在工作副本中

#### Scenario: 提交信息

- **WHEN** 一次发布包含 2026-11-08 的新增照片
- **THEN** 提交信息至少包含日期或条目数量等可读摘要，便于在仓库历史中定位本次发布

### Requirement: 推送与失败恢复

推送 SHALL 发往配置的分支，且 MUST NOT 使用强制推送。推送失败时，本地提交与照片数据 MUST 保持不变，编辑器 SHALL 标记「有未发布改动」并提供重试；重试 MUST 复用已有提交，不得为同一批改动重复生成提交。

#### Scenario: 推送成功

- **WHEN** 本地提交成功且远端接受该分支的更新
- **THEN** 编辑器显示推送成功、提交哈希与时间，并清除未发布标记

#### Scenario: 认证失败

- **WHEN** 推送因凭据缺失、过期或无权限被拒绝
- **THEN** 编辑器提示检查系统 Git 凭据或 SSH 密钥，保留本地提交与数据，允许修复后重试

#### Scenario: 推送被拒绝

- **WHEN** 远端在提交期间接受了其他推送，导致本次推送被拒绝
- **THEN** 编辑器停止并报告需要同步，保留本地提交，不得覆盖远端历史

#### Scenario: 重试不重复提交

- **WHEN** 用户在上次推送失败后再次点击发布，且本地数据没有再变化
- **THEN** 编辑器直接推送已有提交，不创建内容相同的新提交

### Requirement: 发布状态与页面刷新

发布成功后，编辑器 SHALL 提供站点地址与本次提交信息，并说明 GitHub Pages 构建可能需要短暂时间。编辑器 SHOULD 在可获取时展示最近一次 Pages 部署状态；无法获取时 MUST 提供打开仓库 Actions 页面的入口，而不是假装页面已立即更新。

#### Scenario: 发布成功后的提示

- **WHEN** 推送成功
- **THEN** 界面显示提交哈希、推送时间和「GitHub Pages 正在构建」的说明，并提供打开线上站点的链接

#### Scenario: 部署状态不可用

- **WHEN** 编辑器无法读取 GitHub Actions 或 Pages 部署状态
- **THEN** 界面不显示虚假的成功部署状态，改为提供打开仓库 Actions 页面的链接

### Requirement: 发布串行化

同一编辑器实例内，发布操作 MUST 串行执行。发布进行中再次触发发布或修改数据时，编辑器 MUST 阻止并发写入，或等待当前操作结束后再处理，避免产生交错提交与半更新状态。

#### Scenario: 发布进行中再次点击

- **WHEN** 用户在一次发布尚未结束时再次点击「发布」
- **THEN** 编辑器禁用发布入口并提示正在发布，不启动第二个 Git 进程

#### Scenario: 发布中导入照片

- **WHEN** 发布尚未完成时用户完成了一次照片导入
- **THEN** 新条目保留为待发布状态，在当前发布结束后才可进入下一批提交

### Requirement: 仓库兼容性校验

编辑器 SHALL 在发布前验证目标仓库具备本项目约定的数据结构与 GitHub Pages 构建配置：至少存在 `data/` 目录（或可在空仓库中初始化）以及用于构建并部署展示页的 workflow。缺少必要结构时 MUST 停止发布并说明缺失项，不得向不兼容仓库写入无法被展示页读取的数据。

#### Scenario: 兼容的仓库

- **WHEN** 目标仓库包含 `data/` 目录与 `.github/workflows/` 下的 Pages 部署工作流
- **THEN** 编辑器完成兼容性检查并允许发布

#### Scenario: 缺少展示页工作流

- **WHEN** 目标仓库存在 `data/` 但没有 Pages 构建工作流
- **THEN** 编辑器在发布前提示缺少部署配置，不把本地数据推送到该仓库

#### Scenario: 空仓库初始化

- **WHEN** 用户将一个空的 GitHub 仓库配置为目标仓库
- **THEN** 编辑器说明需要先由本项目模板初始化展示页与工作流，或在用户确认后创建最小的 `data/calendar.json` 结构，但不得声称页面已可部署

### Requirement: 凭据与日志安全

编辑器 SHALL 使用系统 Git 凭据管理器、SSH Agent 或用户已有的 Git 配置完成认证，不得自行持久化 HTTPS 访问令牌。所有 Git 命令输出、错误提示与诊断日志中的用户名、令牌和带凭据的 URL MUST 被掩码或移除。

#### Scenario: 使用系统凭据

- **WHEN** 系统已通过 Git Credential Manager 配置仓库凭据
- **THEN** 编辑器无需用户再次输入凭据即可推送，且设置界面不要求填写访问令牌

#### Scenario: 错误日志脱敏

- **WHEN** Git 返回包含 `https://user:secret@host/repo.git` 的错误
- **THEN** 界面与日志中只显示 `https://***@host/repo.git` 或等价的脱敏形式
