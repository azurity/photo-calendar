# Proposal

## Why

单日页的文案目前放在照片下方一张独立的日期纸卡里，与相纸主图割裂：相纸底部白边只印一行日期，既浪费了拍立得最有温度的签名区，也没有形成「在照片上写一句话」的记忆点。现在相纸视觉已经稳定，适合把文案收进白边，并用手写质感强化「记录一天」的私人感。

## What Changes

- 有照片的单日页把相纸底部白边加高，形成一个可容纳 1–3 行文案的签名区，文案直接写在白边里。
- 日期、星期与眉标从独立纸卡迁入相纸白边；移除有照片日期的独立 `.day-copy` 纸卡，页面主体变为「一张写有字的相纸 + 前后导航」。
- 文案采用 CDN 中文手写字体与马克笔质感：手写字形、墨色、轻微倾斜、渗墨阴影与手绘下划线/高亮；字体按 unicode-range 分片加载，CDN 不可用时回退到系统手写字体栈与现有衬线字体，保持可读。
- 相纸使用有上限的响应式宽度，照片保持不裁切；白边增高后控制照片高度与相纸行高，避免溢出、裁切或横向滚动。
- 无照片日期的明信片寄语页保持不变；数据契约、编辑器、文案生成与 Git 发布链路不变。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `calendar-display`: 有照片的单日视图从「照片相纸 + 独立文案纸卡」改为「相纸白边内的日期与手写文案」；相应调整相纸主图、内容层级与可读性要求，并新增手写字体加载失败时的回退约束。

## Impact

- 代码：`apps/web/src/day.ts`（单日 DOM 结构、字体加载成功后的激活）、`apps/web/src/styles.css`（相纸白边、手写文案与响应式）、`apps/web/day.html`（字体 CDN 链接）；相纸相关单元/E2E/axe 测试。
- 依赖：新增一个外部 CDN 手写字体（洪蕾行书，按 unicode-range 分片、免费商用）；不新增 JS 运行时依赖。
- 外部系统：无。数据契约、照片处理、DeepSeek、Git 发布与 GitHub Pages 工作流不变。
- 文档：更新 `docs/visual-language.md` 与 `docs/visual-acceptance.md` 中单日页结构的描述。
- 风险：字体加载引起文案换行与相纸高度跳动；窄屏与长文案（上限 120 字）下白边可能过高；深色主题下相纸仍为浅色，墨色对比需复核。
